## 仍需完善的四项

### 1. 高优先级：补齐标准化后无法直接判断的字段

涉及流程第 2.3 节指标字典、第 8.2 节工具清单。

指标要求识别原始单位、外部负重、计时动作和适用运动类型，但当前 `training_set` 没有保留完整的相关字段。

尤其是 `scripts/normalize.py` 的 `_weight_kg()`：除磅转换外，其他单位直接保留数值写入 `weight_kg`。因此，字段名叫 `weight_kg`，不代表原始单位已经通过校验。

建议增加工具项：

> 计算前建立可回查的动作类型、原始单位及负重语义映射；现有库字段不足时，从对应 Raw 提取到派生事实表。无法确认的记录排除出相关指标，并登记原因。

验收至少覆盖 kg、lb、未知单位、计时、自重和辅助重量，不能仅验证正数乘法。

### 2. 高优先级：明确超级组、递减组的计组和匹配单位

涉及流程第 2.3 节 `training.work_sets`、`template.execution_ratio` 及唯一目标定位键约定。

当前 `scripts/normalize.py` 的 `_normalize_movement()` 会将超级组子动作及递减组子段展开为多条记录；递减子段还会复用父组的 `set_index`。

因此，“一条完成记录算一组”和“模板中的一个目标组”未必是同一个单位。唯一目标键虽然能防止重复计入，但还不能解释：

- 一个递减组的多个重量段如何计组。
- 超级组按轮次还是子动作计数。
- 部分子段完成，能否算目标组完成。

建议分开定义：

- **完成记录段数**：展开后的记录数量。
- **正式组数**：按已登记的结构折算。
- **模板目标组完成数**：按目标组结构和完成条件匹配。

如果初版只支持记录段数，也应明确命名和限制，暂不直接用于模板执行率。

### 3. 中优先级：区分容量的零值与不可计算状态

涉及流程第 2.3 节 `training.volume`。

当前规定“无可计算组则 `null`”，会同时覆盖多种不同情况。建议写成明确的决策表：

| 情况 | 建议输出 |
|---|---|
| 已确认完整覆盖且无训练 | 已记录容量 `0`，注明无训练 |
| 有训练，但只有自重或计时动作 | `null`，注明不适用 |
| 应可计算，但重量或次数缺失 | `null`，注明数据不足 |
| 部分组可计算 | 可计算部分合计，附覆盖率 |

否则已确认休息日和数据缺失日虽然状态不同，容量指标仍容易被下游同样处理。

### 4. 中优先级：拆开饮食差值与比率的准入条件

涉及流程第 2.3 节 `food.target_delta` / `food.target_delta_ratio`，以及步骤 4 的饮食分析规则。

指标字典把差值和比率都限定为“目标大于 0”，但正文仅对相对偏差提出该限制。

建议统一为：

- **差值**：摄入与目标均有效即可计算；若目标确为有效零值，差值仍有定义。
- **比率**：目标必须大于 0。
- 如果接口中的零表示未设置目标，则按缺目标处理，不能当有效零。

此外，第 2.3 节的“平均克数差值”应改为“平均绝对差值，单位随指标”，避免热量指标被误标为克。这里的绝对差值指原单位下的有符号差值（摄入减目标），不是对差值取绝对值；正式修订时可直接采用“平均差值（g 或 kcal）”以避免歧义。
